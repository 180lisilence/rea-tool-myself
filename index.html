把 REA CLI 装进
两个端

REA Tool 是逆向工程分析套件 REA CLI 的图形化双端实现： Windows 原生面板在本机直接驱动 rea 命令；Android 手机端作为轻量前端， 通过局域网 REST / SSE 接口把命令发回电脑执行。两端共用同一套命令索引与 JSON Schema 参数表单， 界面与结果格式完全对齐。

01 / Overview

一个后端，两种交互形态

REA 本身是 Node.js CLI，不能直接跑在 Android 上。项目因此拆成两个端：PC 端把 CLI 包成原生窗口，手机端把 CLI 包成 HTTP 服务再配一个 WebView 前端。命令能力完全一致，只是承载方式不同。

DESKTOP · panel 分支

REA-Panel.exe — Windows 原生控制台

PyQt6 三栏桌面窗口，直接 fork 本机 rea 进程执行分析命令，PyInstaller 打成单文件 exe，双击即用、无需 Python 环境。

  • 左栏 153 个命令按 7 类分组，支持 Ctrl+F 搜索
  • 中栏 由 --schema 自动生成参数表单：enum→下拉、bool→复选、array→JSON、路径→浏览按钮
  • 右栏 结果三视图：JSON 折叠树 / 原始文本 / 图片预览
  • 底部 运行日志、退出码、耗时；Ctrl+Enter 运行
入口 main.py → app/main_window.py → app/rea_backend.py
MOBILE · mobile 分支

REA-Panel-Mobile.apk — 手机端

极简 APK（约 50 KB）：一个原生 WebView 壳加载随包内置的 HTML 界面，界面用 fetch 调电脑上的 HTTP 服务，手机与电脑连同一 WiFi 即可。

  • 本地前端 assets/panel/ 四屏：连接 / 命令 / 参数 / 结果
  • 连接配置 填服务器地址与可选令牌，状态灯实时反映连通性
  • 流式输出 走 SSE /api/stream，长任务逐段回显
  • 结果视图 JSON / 文本切换，一键复制结果
入口 MainActivity.java · 服务 app/rea_server.py
02 / Architecture

工作原理

两条链路共用同一层 rea_backend.py：它负责定位 rea 执行环境、解析命令索引、拉取 JSON Schema、流式执行命令。区别只在于「谁调用它」。

Android 端 = 纯前端 + WebView 壳 局域网 REST / SSE 通道（仅手机端需要） 共用调用层 实际执行者：REA CLI
01

为什么手机端不移植 CLI

REA 依赖 Node 运行时与本机分析引擎，Android 无法直接承载。改为「手机做前端、电脑做执行端」，零成本对齐全部 155 个命令，且 APK 只有 50 KB。

02

Schema 驱动界面

每个命令执行 rea <cmd> --schema --format json，面板据 JSON Schema 现场生成控件，命令增减无需改 UI 代码。

03

双通道流式执行

rea 把日志写 stderr、结构化结果写 stdout。PC 端用 QThread 双线程泵回传，手机端用 SSE event: chunk / done 逐段推送。

04

零联网构建

不用 Electron：本机已有 PyQt6 + PyInstaller，新项目零安装。APK 走免 Gradle 手工链路，只用 Android build-tools，无需下载 Gradle 依赖。

03 / Build pipeline

两条构建链路

两端都做到「一条命令出成品」：build.bat 分别驱动 PyInstaller 与 Android build-tools。构建中间产物不入库，源码、脚本、签名库与成品齐全，可原样重建。

PC 面板 · rea-panel / build.bat
main.py→ PyInstaller --clean --onefile --windowed→ --icon assets/icon.ico --add-data assets→ --exclude-module QtWebEngine* / numpy / PIL→ dist/REA-Panel.exe
# 排除 QtWebEngine 必加，否则体积从 37 MB 涨到 150 MB python -m PyInstaller --clean --noconfirm --name REA-Panel --windowed --onefile ^ --icon assets/icon.ico --add-data "assets;assets" ^ --exclude-module PyQt6.QtWebEngineCore --exclude-module numpy ^ main.py
Android 手机端 · rea-mobile / build_apk.py（免 Gradle 手工链路）
aapt2 compile→ aapt2 link + R.java→ javac -encoding UTF-8→ d8 → classes.dex→ jar uf 写回 dex→ zipalign -f 4→ apksigner sign→ dist/REA-Panel-Mobile.apk
# minSdk 24 / targetSdk 34，debug.keystore 随仓库提供，可原样重签 python build_apk.py # 产物校验：apksigner verify --print-certs dist/REA-Panel-Mobile.apk adb install -r dist/REA-Panel-Mobile.apk

05 / Quick start

开始使用

1

PC 端：开箱即用

下载 REA-Panel.exe 双击运行；或在 panel 分支执行 python main.py 开发模式启动。面板会自动定位托管 node + rea.mjs，回退 npm 全局 rea.cmd / PATH 上的 rea。

2

手机端：先起后端服务

在电脑上执行 python app/rea_server.py（panel 分支），控制台会打印「手机填这个：http://192.168.x.x:8788」。首次运行需允许 Windows 防火墙放行 8788 端口。

3

手机端：安装并连接

安装 REA-Panel-Mobile.apk（Android 7.0+），手机与电脑连同一 WiFi，在「连接」页填入上一步的地址（可选令牌），点「测试连接」，状态灯变绿即可进命令列表。

4

选命令 → 填参数 → 运行

参数表单由 JSON Schema 自动生成，填完点「运行」，结果在 JSON / 文本视图间切换；长任务通过 SSE 逐段回显。快捷键：Ctrl+F 搜索、Ctrl+Enter / F5 运行、Esc 清空搜索。

已知限制

REA 的四个分析引擎（Ghidra / IDA / jadx / Hopper）尚未配置，rea doctor 会报 missing_analysis_engine；不依赖引擎的命令（doctor、compare-*、address-to-file-offset 等）可正常调用。手机端服务默认无令牌，仅在可信局域网使用；如需鉴权可在 rea_server.py 设置 TOKEN 并在手机端填写。
